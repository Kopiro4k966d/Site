# Безопасность админки Crysea

Эта инструкция — для владельца проекта. Всё, что написано в браузере (`admin.js`), — удобство,
а не защита. Реальная граница доступа — на сервере.

## Что уже сделано в коде
- `admin.html`: `noindex`, `no-referrer`, ключ только в памяти вкладки, автовыход через 10 минут простоя,
  сброс ключа при скрытии вкладки, подтверждения для активации, оплаты за видео и выплат.
- `middleware.js` (Edge, корень проекта): прячет `/admin` и `/api/admin/*` с ответом 404 для IP вне списка
  `ADMIN_IP_ALLOWLIST` и ставит заголовки `no-store` и `noindex`.
- `server/admin-guard.js`: проверка `ADMIN_KEY` (fail-closed при коротком ключе, сравнение за постоянное время,
  замедление перебора, блокировка IP после 5 неудач на 15 минут), защитные заголовки, лимит размера тела,
  строгая валидация выдачи подписки, идемпотентность по `Idempotency-Key`, журнал действий.

## Что нужно сделать вам (обязательно)
1. **Сгенерируйте ключ** длиной не меньше 40 символов и сохраните его только в Vercel → Settings → Environment Variables как `ADMIN_KEY`:
   `openssl rand -base64 48`. Не храните его в коде, README и чатах.
2. **Закройте админку снаружи.** Самый надёжный вариант для «только я»: Cloudflare Access (Zero Trust) с
   правилом «разрешить только мой email» перед доменом `/admin*` и `/api/admin*`. Вариант проще: Vercel
   Password Protection, если доступен на вашем тарифе. Вариант `ADMIN_IP_ALLOWLIST` работает только при
   статичном IP.
3. **Подключите guard ко всем обработчикам `/api/admin/*`** в вашем серверном коде:
   ```js
   const guard = require('../../server/admin-guard');
   module.exports = guard.wrap(async (req, res) => { /* ... */ }, { methods: ['POST'] });
   ```
   Для выдачи подписки используйте `guard.validateGrant(req.body)` и `guard.once(req, 'grant', fn)`.
   В текущих файлах нет серверного кода `/api`, поэтому я не могу проверить эту часть — её нужно подключить в вашем репозитории.
4. **Журнал.** Замените `audit.sink` на запись в таблицу `audit_log` (кто, когда, IP, действие, сумма).
5. **Общая память для лимитов.** В serverless-окружении память не общая между экземплярами. Перенесите
   `store` на Redis или Vercel KV, иначе лимит попыток работает не везде.
6. **База данных.** Включите Row Level Security (если Supabase/Postgres): клиентский ключ не должен давать
   доступа к таблицам подписок, платежей и партнёров. Выдавать подписки может только серверный код с service-ключом,
   который не попадает в браузер.
7. **Аккаунты.** Включите двухфакторную аутентификацию на Vercel, GitHub, домене и почте cryseasupport@gmail.com.
8. **Проверьте после деплоя:** открыть `/admin` без входа в режиме инкогнито с другого IP — должна быть 404 или
   запрос логина; `POST /api/admin/...` без ключа — 401; пять неверных ключей — 429.

## Чего эта защита не даёт
- Не защитит от утечки самого `ADMIN_KEY` с вашего компьютера или из аккаунта Vercel.
- Не заменяет аудит платежей у платёжного провайдера.
- Блокировка после пяти неудач может затронуть и вас, если вы ошиблись ключом несколько раз: подождите 15 минут.
